# Инструменты и параметры

Справочник по версии 0.4.1. Фактическая MCP-схема подключённого сервера имеет приоритет. Исходники: [transactions.ts](https://github.com/artarasov/zenmoney-mcp/blob/f88e75581b7df341424ef64bd554e32d2ce9335b/src/tools/transactions.ts), [state.ts](https://github.com/artarasov/zenmoney-mcp/blob/f88e75581b7df341424ef64bd554e32d2ce9335b/src/state.ts).

| Инструмент | Параметры и смысл |
|---|---|
| `sync_data` | `force_full` — boolean, по умолчанию false. Первый sync загружает все сущности; последующие — изменения. |
| `list_accounts` | `include_archived` — boolean, по умолчанию false. Возвращает UUID, валюту и баланс. |
| `list_categories` | Без параметров. Категории и их иерархия с UUID. |
| `list_merchants` | Без параметров. Известные получатели/продавцы. |
| `suggest_category` | `payee` — название получателя. Рекомендации по категории и продавцу. |
| `list_transactions` | `days` (по умолчанию 30), `start_date`, `end_date`, `account`, `category`, `limit` (по умолчанию 50). Явные границы заменяют `days`; обе границы включены. Нет фильтра payee или типа операции. |
| `add_expense` | Обязательные `account`, `amount`, `date`; необязательные `category`, `payee`, `comment`. |
| `add_income` | Обязательные `account`, `amount`, `date`; необязательные `category`, `payee`, `comment`. |
| `add_transfer` | `from_account`, `to_account`, `date`; суммы через `amount` либо `outcome_amount` и `income_amount`; необязательный `comment`. Для разных валют явно передавай обе суммы. |
| `update_transaction` | Обязательный `id` (UUID или массив UUID) и хотя бы одно изменяемое поле. Поля перечислены ниже. |

## Обновление

- `category`: название/UUID или массив; `""` или `[]` снимает категории. Заполнение этого поля заменяет набор категорий, а не дополняет его.
- `amount`: положительная сумма обычного расхода или дохода. Для перевода используй `outcome_amount` и `income_amount`.
- `date`: `YYYY-MM-DD`.
- `payee`, `comment`: строки; пустая строка очищает поле.
- `account`: смена счёта обычного расхода/дохода.
- `from_account`, `to_account`: смена счетов перевода.
- `outcome_amount`, `income_amount`: неотрицательные суммы соответствующих сторон; не зануляй сторону без явного намерения пользователя.

Передавай только поля, которые нужно изменить. Отсутствующее поле сохраняется, пустое значение может очищать его. Один массив UUID применяет одинаковые изменения к каждому элементу. Подбор UUID по неоднозначному описанию выполняется до вызова обновления.

## Примеры аргументов

Плейсхолдеры ниже необходимо заменить реальными UUID из справочников. Они не являются готовыми запросами на запись.

Расход в валюте выбранного счёта:

```json
{"account":"ACCOUNT_UUID","amount":500,"date":"2026-10-08","category":"CATEGORY_UUID","payee":"Кофейня"}
```

Межвалютный перевод, если пользователь указал фактические суммы:

```json
{"from_account":"USD_ACCOUNT_UUID","to_account":"EUR_ACCOUNT_UUID","outcome_amount":1000,"income_amount":920,"date":"2026-10-08"}
```

Смена категории выбранных операций:

```json
{"id":["TRANSACTION_UUID_1","TRANSACTION_UUID_2"],"category":"CATEGORY_UUID"}
```

## Полнота и расчёты

Для месячной сводки передавай обе даты и явный лимит. Результат содержит текстовые строки с типом, суммой, категориями и UUID; это не готовый агрегат. Получателей ищи локально в полной выборке, а не через несуществующий параметр `payee`.

Ровно N строк при `limit=N` не доказывает полноту. Увеличь лимит или раздели период. Не сокращай выборку до первых N записей ради экономии контекста, если пользователь запросил полный итог; при ограничениях покажи частичный результат.

Для сумм используй десятичную арифметику или целые минимальные денежные единицы. Группируй по валютам, исключай переводы из расходов, учитывай категории потомков только при запросе родительской группы. При многокатегорийных операциях избегай двойного счёта в общем итоге и объясняй возможное пересечение групп.

Сервер не предоставляет инструменты удаления транзакций, создания счетов/категорий, бюджетов или банковского перевода. Не обещай эти возможности и не подменяй их несанкционированными прямыми вызовами API.
