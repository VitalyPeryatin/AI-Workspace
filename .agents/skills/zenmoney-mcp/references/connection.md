# Подключение ZenMoney MCP

Проверено по исходникам версии 0.4.1, commit `f88e75581b7df341424ef64bd554e32d2ce9335b`, 8 октября 2026 года. При другой версии сверяй живые схемы инструментов и документацию проекта.

Источники: [репозиторий](https://github.com/artarasov/zenmoney-mcp), [точка входа](https://github.com/artarasov/zenmoney-mcp/blob/f88e75581b7df341424ef64bd554e32d2ce9335b/src/index.ts), [MCP в Codex](https://developers.openai.com/codex/mcp).

## Требования

- Node.js >= 18 и доступный `npx`.
- Аккаунт ZenMoney и `ZENMONEY_TOKEN`. README проекта предлагает получить токен через [zerro.app/token](https://zerro.app/token). Это отдельный сайт, указанный автором проекта; пользователь сам проходит авторизацию. Не проси пароль ZenMoney или публикацию токена в чате.
- Сервер использует stdio и запускается командой `npx -y zenmoney-mcp`. Он не предоставляет HTTP URL или MCP OAuth-login.

При запросе подключения проверь `node --version`, `command -v npx` и существующую запись сервера, не печатая секретные значения. При чтении конфигурации извлекай только несекретные поля вместо полного `cat` или неотредактированного вывода CLI.

## Codex

Добавляй или обновляй только таблицу `mcp_servers.zenmoney` в пользовательском конфиге `${CODEX_HOME:-$HOME/.codex}/config.toml`, сохраняя остальные настройки. Предпочитай существующий способ хранения секретов пользователя.

Если токен уже доступен в окружении самого процесса Codex:

```toml
[mcp_servers.zenmoney]
command = "npx"
args = ["-y", "zenmoney-mcp"]
env_vars = ["ZENMONEY_TOKEN"]
```

`env_vars` передаёт имеющуюся переменную, но не создаёт её. Экспорт в отдельном терминале не обновляет окружение уже работающего desktop-приложения.

Для локального desktop-запуска без унаследованной переменной сервер поддерживает `.env` через `dotenv/config`: пользователь может положить файл с `ZENMONEY_TOKEN=...` в отдельный приватный каталог вне репозитория. Установи права 700 на каталог и 600 на файл. В конфиге укажи абсолютный путь к этому каталогу:

```toml
[mcp_servers.zenmoney]
command = "npx"
args = ["-y", "zenmoney-mcp"]
cwd = "/absolute/path/to/private/zenmoney-directory"
```

Путь в примере заменяется фактическим существующим каталогом. Не сохраняй секрет в каталоге скилла. Если `ZENMONEY_TOKEN` уже задан в окружении, он имеет приоритет над `.env`; при ошибке авторизации проверь источник без раскрытия значения.

Если desktop-процесс не видит `npx`, используй обнаруженный абсолютный путь; учитывай, что `npx` также должен находить `node` в PATH. Не прописывай предполагаемый путь Homebrew без проверки.

CLI также поддерживает `codex mcp add zenmoney -- npx -y zenmoney-mcp`, но запись сервера всё равно нуждается в источнике токена. Не передавай настоящий токен в командной строке `--env`: он может попасть в историю и вывод.

После изменения настроек перезапусти подключение или открой новую сессию. Проверь появление инструментов, затем выполни только `sync_data` и `list_accounts` для проверки доступа. Успешное изменение TOML не доказывает работоспособность MCP. Без токена честно сообщи, что подготовлена конфигурация, а подключение ещё не проверено.

## Другие MCP-клиенты

В Claude Desktop или Cursor применяется JSON `mcpServers`, а не Codex TOML. Используй соответствующий конфиг клиента и ту же stdio-команду. Источник `ZENMONEY_TOKEN` задаётся через поддерживаемое клиентом окружение или приватный `.env` с явным `cwd`; конкретные возможности сверяй с клиентом. Не записывай Claude-конфиг в Codex.

## Диагностика

- `ZENMONEY_TOKEN environment variable is required`: токен не попал в окружение, неверен `cwd` или нет `.env`.
- Ошибка запуска / command not found: проверь Node, `npx` и PATH desktop-приложения.
- API 401/403: проверь токен и доступ аккаунта; не повторяй авторизацию бесконечно.
- `Data not synced yet`: вызови `sync_data` после запуска сервера.
- Медленная первая загрузка npm или полный sync: при необходимости увеличь `startup_timeout_sec` или `tool_timeout_sec`, сохраняя разумный конечный таймаут.
- Проверка доступа выполняется чтением; не создавай тестовый расход в личном аккаунте.
