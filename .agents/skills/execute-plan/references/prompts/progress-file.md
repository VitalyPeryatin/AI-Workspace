# Файл прогресса

Родительский агент ведёт файл прогресса по пути `docs/progress/progress-<plan-name>.txt` (имя — от stem'а файла плана, например, `fix-issues.md` → `docs/progress/progress-fix-issues.txt`). Этот файл накапливает контекст по всем фазам, чтобы агенты ревью и фиксер могли видеть, что произошло до них.

## Когда записывать

Родительский агент дописывает в файл прогресса в этих точках через `append-progress.sh` (не используй `cat >>` или прямую запись; всегда дописывай через скрипт):

**В начале:**
```
# progress
Plan: <путь-к-файлу-плана>
Branch: <имя-ветки>
Started: <временная-метка>
---
```

**После завершения каждой задачи:**
```
[task] Task N: <заголовок> — completed
```

**После провала каждой задачи:**
```
[task] Task N: <заголовок> — FAILED (retry N)
```

**Перед фазой ревью:**
```
--- review phase N: <тип> ---
```

**После возврата агентов ревью (перед фиксером):**
```
[review] iteration N findings:
<полный вывод агента вставлен сюда>
```

**После завершения фиксера:**
```
[fixer] iteration N: <отчёт фикстера о том, что исправлено/отброшено>
```

**При завершении:**
```
---
Completed: <временная-метка>
```

## Как передавать

- Передай путь к файлу прогресса в промпт агента-фиксера — добавь его после ссылки на файл плана
- Агентам ревью файл прогресса НЕ нужен (они смотрят на состояние репозитория)
- Фиксер использует его, чтобы понять, что предыдущие итерации нашли и исправили
