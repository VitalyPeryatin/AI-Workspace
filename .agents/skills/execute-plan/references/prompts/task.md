# Промпт задачи для субагента

Прочитай файл плана по пути PLAN_FILE_PATH. Найди ПЕРВУЮ секцию Task (### Task N: или ### Iteration N:), в которой есть незавершённые чекбоксы ([ ]).

Рабочая директория: WORK_DIR
Если WORK_DIR не пуста, ты работаешь в изолированном git worktree. ВСЕ операции с файлами (Read, Write, Edit, Glob, Grep) ДОЛЖНЫ использовать абсолютные пути, начинающиеся с WORK_DIR. ВСЕ вызовы Bash tool ДОЛЖНЫ включать `workdir: WORK_DIR`. PLAN_FILE_PATH и PROGRESS_FILE_PATH уже являются абсолютными путями внутри worktree.

Если в секции Task есть чекбоксы [ ], которые ты не можешь завершить (ручное тестирование, проверка развёртывания, внешние проверки): отметь их как [x] с пометкой вроде "[x] manual test (skipped - not automatable)" и продолжай.

КРИТИЧЕСКОЕ ОГРАНИЧЕНИЕ: Завершай ОДНУ секцию Task за итерацию.
Секция Task — это заголовок "### Task N:" или "### Iteration N:" со всеми чекбоксами под ним.
Завершить ВСЕ чекбоксы в этой секции, затем СТОП.
НЕ переходи к следующей секции.

ШАГ 1 - РЕАЛИЗАЦИЯ:
- Прочитай секции Overview и Context плана, чтобы понять работу
- Реализуй ВСЕ пункты в текущей секции Task (все чекбоксы [ ] под ней)
- Напиши тесты для реализации

ШАГ 2 - ВАЛИДАЦИЯ:
- Запусти команды тестирования и линтинга, указанные в плане (например, "./gradlew :module:test", "./gradlew :module:detekt ./..." и т.д.)
- Исправь любые падения, повторяй пока вся валидация не пройдёт

ШАГ 3 - ЗАВЕРШЕНИЕ (после прохождения валидации):
- Отредактируй PLAN_FILE_PATH и замени [ ] на [x] для каждого чекбокса, который ты реализовал в текущей секции Task
- Если секции Task завершены, но Success criteria, Overview или Context содержат [ ] пункты, которые реализация удовлетворяет — отметь их тоже как [x]
- Закоммить все изменения через скрипт: bash SKILL_DIR/scripts/stage-and-commit.sh "feat: <краткое описание задачи>" file1 file2 ...
  Укажи все изменённые файлы явно (исходные файлы, файлы тестов, файл плана)

ШАГ 4 - ЗАПИСЬ ПРОГРЕССА (после коммита):
Запиши строку-заголовок: bash SKILL_DIR/scripts/append-progress.sh PROGRESS_FILE_PATH "task N: <заголовок>"
Затем запиши детали через echo, направленный в скрипт:
echo "- modified: <файлы>
- implemented: <что сделано>
- tests: <какие тесты добавлены, или почему пропущены>
- validation: <какие команды прошли>" | bash SKILL_DIR/scripts/append-progress.sh PROGRESS_FILE_PATH

СТОП после записи прогресса.

Если любая фаза проваливается после разумных попыток исправления, запиши провал в PROGRESS_FILE_PATH и сообщи, что именно провалилось.

ОДНА секция task за запуск. После коммита и записи прогресса — СТОП.
