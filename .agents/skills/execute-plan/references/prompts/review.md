# Промпт оркестрации ревью

Агент ревью запускает индивидуальные агенты ревью, собирает находки и сообщает результат. Он НИЧЕГО не исправляет — оркестратор передаёт находки фикстеру.

Рабочая директория: WORK_DIR
Если WORK_DIR не пуста, ты работаешь в изолированном git worktree. ВСЕ операции с файлами (Read, Write, Edit, Glob, Grep) ДОЛЖНЫ использовать абсолютные пути, начинающиеся с WORK_DIR. ВСЕ вызовы Bash tool ДОЛЖНЫ включать `workdir: WORK_DIR`. PLAN_FILE_PATH и PROGRESS_FILE_PATH уже являются абсолютными путями внутри worktree.

## Фаза 1 — комплексная (4 агента)

Используется, когда REVIEW_PHASE равен comprehensive.

Прочитай файл промпта каждого агента из AGENTS_DIR:
- quality.txt
- implementation.txt
- testing.txt
- simplification.txt

Добавь в начало каждого промпта агента:

"КРИТИЧЕСКИ: Ты — ревьюер ТОЛЬКО ЧТЕНИЯ. НЕ запускай git stash, git checkout, git reset или любую команду, модифицирующую рабочее дерево. Другие агенты работают параллельно. Используй только git diff, git log, git show и чтение файлов.

Запусти `git diff DEFAULT_BRANCH...HEAD`, чтобы увидеть все изменения. Читай фактические исходные файлы для полного контекста — не проводи ревью только по diff'у.

Файл плана по пути PLAN_FILE_PATH описывает цель и требования — используй его, чтобы понять, что код должен делать.

Прочитай файл прогресса по пути PROGRESS_FILE_PATH для контекста о предыдущих итерациях ревью и исправлениях. Переоцени все находки независимо — предыдущие исправления могут быть неполными или неверными, а ранее отклонённые проблемы могут оказаться реальными."

Запусти все 4 агента параллельно — отправь ВСЕ 4 вызова Task tool в ОДНОМ сообщении. Используй `subagent_type: "general"` для каждого. Включи полный промпт агента (с добавленным текстом выше) как промпт задачи.

После возврата ВСЕХ 4 агентов:
- Собери и дедуплицируй находки всех агентов
- Одинаковый file:line + одинаковая проблема — объединить
- Сообщи ВСЕ находки — НЕ проверяй, не исправляй и не отбрасывай ни одну
- Включай ТОЛЬКО тех агентов, которые сообщили о реальных проблемах — опускай агентов, которые ничего не нашли
- Укажи каждую находку как: имя-агента: файл:строка — описание

## Фаза 2 — только критичное (2 агента)

Используется, когда REVIEW_PHASE равен critical.

Прочитай только quality.txt и implementation.txt из AGENTS_DIR. Добавь в начало каждого промпта агента: "Сообщай ТОЛЬКО о критичных и мажорных проблемах — багах, уязвимостях безопасности, рисках потери данных, сломанной функциональности, некорректной логике, отсутствующей критичной обработке ошибок. Игнорируй стиль, минорные улучшения, предложения."

Запусти обоих параллельно. Тот же формат, что и в Фазе 1.

После возврата ОБЕИХ агентов:
- Та же сборка/дедупликация, что и в Фазе 1
- Оставь только критичные/мажорные находки
