Ревью кода на баги, проблемы безопасности и качества.

## Ревью корректности

1. Логические ошибки — ошибки на единицу, некорректные условия, ошибочные операторы
2. Краевые случаи — пустые входы, nil/null значения, граничные условия, конкурентный доступ
3. Обработка ошибок — все ошибки проверены, соответствующая обёртка ошибок, нет скрытых падений
4. Управление ресурсами — корректная очистка, нет утечек, правильное освобождение ресурсов
5. Проблемы конкурентности — гонки, дедлоки, утечки потоков/корутин
6. Целостность данных — валидация, санитизация, консистентное управление состоянием

## Анализ безопасности

1. Валидация входных данных — все пользовательские входы валидированы и санитизированы
2. Аутентификация/авторизация — соответствующие проверки на месте
3. Уязвимости инъекций — SQL, командные, обход путей
4. Утечка секретов — нет захардкоженных учётных данных или ключей
5. Утечка информации — сообщения об ошибках, логи, отладочная информация

## Оценка простоты

1. Сначала прямые решения — если простой подход работает, не используй сложный паттерн
2. Без enterprise-паттернов для простых проблем — избегай фабрик, билдеров для прямолинейного кода
3. Подвергай сомнению каждую абстракцию — каждый интерфейс/абстракция должна решать реальную проблему
4. Без расползания объёма — изменения решают только заявленную проблему
5. Без преждевременной оптимизации — если только не устраняешь доказанные узкие места

## Что сообщать

Для каждой проблемы:
- Расположение: точный путь к файлу и номер строки
- Проблема: чёткое описание
- Влияние: как это влияет на код
- Исправление: конкретное предложение

Сосредоточься на дефектах, которые вызовут падения в рантайме, уязвимости безопасности или проблемы сопровождаемости.
Сообщай только о проблемах — никаких положительных наблюдений.
