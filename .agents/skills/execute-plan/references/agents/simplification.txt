Обнаружение переусложнённого и перегруженного кода — код, который работает, но сложнее, чем необходимо.

## Избыточные слои абстракции

- Обёртка без пользы — метод просто вызывает другой метод с той же сигнатурой
- Фабрика для единственной реализации — паттерн фабрики, когда существует только один конкретный тип
- Интерфейс на стороне производителя — интерфейс определён там, где реализован, а не там, где потребляется
- Антипаттерн "слоёный пирог" — handler -> service -> repository, когда каждый просто пропускает через себя
- Избыточные DTO/Mapper — несколько типов, представляющих одни и те же данные, с функциями конвертации

## Преждевременное обобщение

- Универсальное решение для конкретной проблемы — event bus для одного типа события
- Объекты конфигурации для 2-3 опций — паттерн options, когда прямых параметров достаточно
- Архитектура плагинов для фиксированной функциональности — точки расширения, которые ничего не расширяет
- Перегруженная структура — один тип, обрабатывающий все вариации с множеством опциональных полей

## Необходимая косвенность

- Транзитные обёртки — методы, которые только делегируют зависимостям
- Избыточное цепочечное вызовы методов — паттерн builder для простых конструкций
- Интерфейсы, оборачивающие примитивы — кастомные типы для типов стандартной библиотеки
- Нагромождение middleware — несколько middleware, которые могут быть одним

## Избыточное прогнозирование на будущее

- Неиспользуемые точки расширения — хуки, коллбэки, плагины без вызывающих
- Версионированные внутренние API — v1/v2, когда используется только одна версия
- Фича-флаги для постоянных решений — флаги, которые всегда вкл/выкл

## Необходимые фоллбэки

- Фоллбэк, который никогда не срабатывает — условия дефолтного пути никогда не выполняются
- Legacy-режим на всякий случай — старый путь кода всегда отключён
- Двойные реализации — старая + новая логика, когда у старой нет вызывающих
- Тихие фоллбэки, скрывающие проблемы — перехват ошибок и фоллбэк вместо быстрого падения

## Преждевременная оптимизация

- Кеширование редко используемых данных — кеш для данных, читаемых один раз при старте
- Кастомные структуры данных — сложные структуры, когда массивов/map достаточно
- Пулы воркеров для эпизодических задач — пулинг для операций в час
- Избыточное пулинг соединений — сложное пулинг для одного соединения

## Что сообщать

Для каждой находки:
- Расположение: файл и ссылка на строку
- Паттерн: какой паттерн переусложнения обнаружен
- Проблема: почему это добавляет ненужную сложность
- Упрощение: как выглядел бы более простой код
- Усилие: тривиальное/маленькое/среднее/большое

Сообщай только о проблемах — никаких положительных наблюдений.
